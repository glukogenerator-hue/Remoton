## 3a. Реализовано 2026-11-15 (в рабочем дереве, не выкачено)

Шесть серверных функций из питча «какие функции добавить» — без обновления агентов, кроме правки апдейтеров:

1. **Блокировка входа.** `Login.razor` включил `lockoutOnFailure: true` (раньше Blazor-вход блокировку не считал), в `Program.cs` явные параметры: 10 неудач → 15 минут. README обновлён.
2. **Автооповещения «Device offline».** `DeviceOfflineAlertService` (раз в час, после минуты от старта), `DataService.GenerateOfflineDeviceAlerts`, порог `OfflineDeviceAlertThresholdInDays` в Server Config (по умолчанию 7, 0 = выкл). Дедупликация: алерт живёт, пока устройство снова не выйдет на связь (CreatedOn > LastOnline).
3. **Дашборд версий агентов.** Страница `/agent-versions` (+ пункт меню): версии → сколько устройств, онлайн/офлайн, последнее появление; бейджи current/outdated относительно версии сервера.
4. **Журнал подключений RC.** Сущность `RemoteControlSessionLog` (без внешних ключей), запись в `ViewerHub` при старте сеанса и при отключении наблюдателя; вкладка Connections на DeviceDetails (последние 200 записей); чистится по сроку хранения данных.
5. **История CPU/RAM/диска.** Сущность `DeviceMetricSample`, точка раз в 15 минут при обновлении состояния устройства; спарклайны за 24 часа на вкладке Details (`Sparkline.razor`, SVG); чистится по сроку хранения.
6. **Поэтапная раскатка агентов.** Новый `GET /api/AgentUpdate/CheckPackage/{platform}?deviceId=X`: агент проверяет обновление через API вместо статического HEAD. Сервер решает по `AgentUpdateWaveDeviceGroups` (Server Config): устройство вне волн всегда получает 304. ETag — SHA-256 пакета с кэшем по mtime/размеру. Апдейтеры Win/Linux/Mac переехали на новый URL. **Гейтинг заработает только после того, как волна агентов с этой проверкой сама разойдётся по парку** — старые агенты проверяют статический файл и обновляются без ограничений.
   **Инцидент при выкатке 2026-11-15:** установка пишет в `etag.txt` статический ETag файла (`Install-Remotely.ps1:127`), который не совпадает с ETag эндпоинта — агенты на свежей версии зацикливались «есть обновление → скачать → переустановить». Исправлено серверно: CheckPackage отдаёт 304 устройству, чья версия равна самой свежей, известной серверу (максимум по `Device.AgentVersion`), независимо от ETag. Правило на будущее: сверять обновления по версии устройства, ETag — вторичен.
   Замечен при выкладке и старый баг (не из этих правок): вкладка Remote Logs на свежем circuit падает «User is not set» (`CircuitConnection.get_User` при активации вкладки) — разобрать отдельно.
7. **Чистый лог агента.** `FileLogger` (Shared): категориям `System.Net.Http.*` больше не разрешён Information — HttpClientFactory писал 4 строки на каждый запрос, дублируя URL; `Log` теперь сам проверяет `IsEnabled` (часть вызовов MEL приходит без неё); стек scopes стал `AsyncLocal` вместо общего статического (scopes HTTP-обработчиков подмешивались в чужие строки); запись синхронная — порядок строк больше не меняется. Эти правки едут с волной агента.

Миграции: Sqlite — одна `20261115100101_Add_AuditLogsAndMetrics` (обе новые таблицы); SqlServer и PostgreSql — по две (`Add_RemoteControlSessionLogs`, `Add_DeviceMetricSamples`). Применены на локальной базе; сервер стартует без ошибок; `CheckPackage` проверен curl'ом (200 + ETag, повторный запрос → 304). Гейтинг-развилку по группам на живых устройствах не проверяли (в локальной базе нет устройств).

## 4. Риски

- **Старые агенты.** Любая правка в агенте не действует, пока машины не обновились. Из 70 записей 24 на сборках старше текущей, но все они офлайн; 6 из них выходили вчера, остальные — 13-29 октября и раньше.
- **Выкладка руками.** Сборка пакетов теперь в CI, но выкладка на сервер — по-прежнему `scp` + `docker cp`/образ. Легко получить рассинхрон версий сервера и агента.
- **Разлогин при выкладке.** Ключи защиты данных теперь лежат в томе AppData (#17), значит перезапуск контейнера не должен рвать сессии. На ближайшей выкладке это надо подтвердить, а не считать решённым.
- **Тонкое покрытие тестами** в местах, где баги и появляются: ввод, буфер, сеть.
