# Remoton

Решение для удалённого управления компьютерами и удалённого выполнения скриптов. Построено на .NET, Blazor и SignalR Core.

[![CI](https://github.com/glukogenerator-hue/Remoton/actions/workflows/ci.yml/badge.svg?branch=master)](https://github.com/glukogenerator-hue/Remoton/actions/workflows/ci.yml)

![image](.github/media/ask-remote.png)

## О проекте

Remoton — форк проекта [Remotely](https://github.com/immense/Remotely) (immense), распространяемого по лицензии GNU GPL v3. Лицензия сохранена (см. файл `LICENSE`), авторство исходного проекта принадлежит его разработчикам.

> **Внутренние имена остались прежними.** Пространства имён, имена сборок (`Remotely_Server.dll`, `Remotely_Agent.exe`), папки установки (`%ProgramData%\Remotely`, `\Program Files\Remotely`), файл базы `Remotely.db`, контейнер `remotely` и переменные окружения `Remotely_*` не переименованы. От них зависят уже установленные агенты и существующие развёртывания, поэтому в командах и путях ниже они встречаются в старом написании.

## Что изменено в форке

- **Сервер работает на .NET 10.** Агент и клиенты удалённого рабочего стола пока на .NET 8. Библиотека `Shared` собирается под обе версии. Старые агенты подключаются к новому серверу без изменений.
- **Обновлены зависимости, закрыты известные уязвимости.** Проверку выполняет CI на каждом коммите (`dotnet list package --vulnerable`).
- **Исправлена передача клавиатуры.** Символы вводятся как Unicode, поэтому работает любая раскладка и русские буквы. Горячие клавиши (Ctrl, Alt, Win) передаются по физической клавише (`KeyboardEvent.code`). Нужен новый агент на управляемой машине.
- **Ускорена передача видео.** Браузер обрабатывает все готовые кадры, а не один за тик `requestAnimationFrame`, и не замирает в фоновой вкладке. Агент снижает качество JPEG (80 → 35) и ограничивает частоту кадров, когда канал не справляется. Для адаптивного качества нужен новый агент.
- **Исправления безопасности.** Фильтры авторизации API при ошибке отклоняют запрос, а не пропускают его. Закрыт XSS через `innerHTML` в веб-клиенте управления.
- **Исправлена фильтрация устройств на портале.** Устройства из других групп больше не попадают в список выбранной Device Group.

## Известные ограничения

- Хабы агентов (`AgentHub`, `DesktopHub`, `ViewerHub`) принимают подключения без отдельной проверки секрета устройства. Это особенность исходного проекта. Закрывайте доступ к серверу сетевыми средствами и обратным прокси, пока это не исправлено.
- Swagger включён во всех окружениях, а политика паролей Identity мягкая (по умолчанию). Рекомендуется закрыть `/swagger` на уровне прокси и задать более строгие требования к паролям.
- Не рекомендуется выставлять сервер в интернет без обратного прокси и HTTPS.

## Быстрый старт (Docker)

Готового публичного образа у форка нет, образ собирается из исходников. Установщики агентов (`wwwroot/Content/*.zip`) в репозиторий не входят, их нужно собрать (раздел «Сборка агентов») и положить в `Server/wwwroot/Content` до сборки образа, иначе агенты нельзя будет установить с сервера.

```
git clone https://github.com/glukogenerator-hue/Remoton.git
cd Remoton
dotnet publish Server/Server.csproj -c Release -p:LibraryRestore=false -o Server/bin/publish
docker build -f Server/Dockerfile -t remoton/server:latest .
mkdir -p /var/www/remotely
```

Затем в `docker-compose/docker-compose.yml` замените `image: immybot/remotely:latest` на `image: remoton/server:latest` и запустите:

```
docker compose -f docker-compose/docker-compose.yml up -d
```

Этот путь сборки образа в форке на практике не проверялся. На рабочем сервере образ собирается иначе (см. «Установка без доступа к интернету»).

### Установка без доступа к интернету

Если на хосте Docker нет доступа к `mcr.microsoft.com` и Docker Hub, образ можно собрать локально на базе уже имеющегося образа Remotely, заменив только сервер:

1. Соберите самодостаточный сервер: `dotnet publish Server/Server.csproj -c Release -r linux-x64 --self-contained true -p:LibraryRestore=false -o publish`.
2. Скопируйте каталог на хост и создайте `Dockerfile` на базе существующего образа. Он удаляет из `/app` всё, кроме `wwwroot/Content` (установщики агентов) и `AppData` (данные), копирует новую сборку и запускает `./Remotely_Server`.
3. На хостах с большим числом контейнеров добавьте в окружение `DOTNET_USE_POLLING_FILE_WATCHER=1`, иначе .NET 10 может упасть при старте из-за лимита `inotify` (`The configured user limit (128) on the number of inotify instances has been reached`).

Перед заменой сервера обязательно сделайте резервную копию базы (`sqlite3 Remotely.db ".backup копия.db"`) и сохраните прежний `docker-compose.yml`.

## Важно: HTTPS и обратные прокси

Единственный поддерживаемый обратный прокси — Caddy, и только когда он напрямую смотрит в интернет. Конфигурация Caddy по умолчанию даёт всё необходимое ASP.NET Core и SignalR.

Если возникают сетевые проблемы с другой схемой (дополнительный межсетевой экран, Nginx и т. п.), ищите помощи в сообществе. Разработчики не могут поддерживать все возможные окружения.

За обратным прокси ASP.NET Core требует заголовки `X-Forwarded-Proto`, `X-Forwarded-Host` и `X-Forwarded-For`. Они задают схему (http/https), адрес исходного запроса и IP клиента. Полученные схема и адрес подставляются в установщики и клиентские приложения, чтобы они знали, куда отправлять запросы. IP клиента показывается в информации об устройстве.

Код Remoton сам эти значения не разбирает, это делает встроенное ПО ASP.NET Core. Если значения не такие, как ожидаются, значит, заголовки отсутствуют, содержат неверные значения, имеют неверный формат или пришли не через цепочку известных прокси.

Чтобы избежать подмены, ASP.NET Core по умолчанию принимает пересылаемые заголовки только с адресов loopback. Дополнительно сервер добавляет IP шлюза Docker из `docker-compose.yml`, который задаётся переменной `Remotely_ApplicationOptions__DockerGatewayIp` (в стандартном compose это `172.28.0.1`). При другой конфигурации добавьте все адреса межсетевых экранов и обратных прокси в массив `KnownProxies` на странице Server Config. В прежних версиях compose переменная называлась `DockerGateway`, и сервер её не читал, используйте именно `DockerGatewayIp`.

Если настроить прокси правильно не получается, можно хотя бы принудительно включить схему HTTPS параметром `Force Client HTTPS` на странице Server Config.

Документация Microsoft: https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/proxy-load-balancer

## После установки

- Данные Remoton сохраняются в контейнере в `/app/AppData`, этот каталог смонтирован в `/var/www/remotely/` на хосте Docker.
- В нём лежат `Remotely.db` и журналы сервера.
  - Эти файлы сохраняются при удалении и пересоздании контейнеров.
  - При переходе с версии без Docker замените файл базы файлом из прежней установки.
- Для публикации в интернет используйте Caddy как обратный прокси.
- При первом запуске создайте учётную запись кнопкой `Register` на главной странице.
  - Эта учётная запись станет администратором сервера и администратором организации.
  - Для неё автоматически создаётся организация.
    - Организации объединяют пользователей, устройства и другие данные в один пул.
    - По умолчанию на сервере может существовать только одна организация.
    - Кнопка `Register` после этого исчезает, самостоятельно создать учётную запись больше нельзя.
    - Чтобы разрешить самостоятельную регистрацию, увеличьте `MaxOrganizationCount` или задайте -1 (см. раздел «Конфигурация»).
- После перезапуска контейнера пользователям может потребоваться войти заново, а открытые вкладки с формами нужно обновить.

## Журналирование HTTP

Можно включить журналирование HTTP, чтобы видеть все запросы и ответы, включая заголовки, в журналах сервера. Это помогает отлаживать обратные прокси, API и SignalR. Параметр включается на странице Server Config.

После изменения контейнер нужно перезапустить.

## Сборка и отладка

Для сборки сервера и клиентов нужны:

- **.NET SDK 10** (версия закреплена в `global.json`). Один SDK 10 собирает и сервер (.NET 10), и агента с клиентами (.NET 8).
- Git.
- Для отладки удобна Visual Studio 2022/2026 или JetBrains Rider со всеми рабочими нагрузками .NET, но для сборки из командной строки достаточно SDK.

TypeScript веб-клиента (`Server/wwwroot/src`) компилируется при сборке сервера пакетом `Microsoft.TypeScript.MSBuild`. Скомпилированные `.js` и `.js.map` хранятся в репозитории рядом с `.ts`, поэтому после правки `.ts` собирайте сервер и коммитьте обновлённые файлы.

```
git clone https://github.com/glukogenerator-hue/Remoton.git
cd Remoton
dotnet build Remotely.sln -p:LibraryRestore=false
dotnet test Tests/Shared.Tests/Shared.Tests.csproj -p:LibraryRestore=false
dotnet test Tests/Server.Tests/Server.Tests.csproj -p:LibraryRestore=false
```

Параметр `-p:LibraryRestore=false` отключает восстановление JS-библиотек через Library Manager. Он нужен, если сборка падает с ошибкой `LIB002` (провайдер unpkg не разрешает версию). Нужные библиотеки уже лежат в `Server/wwwroot/lib`.

- При отладке агент использует заранее заданный идентификатор устройства и подключается к `https://localhost:5001`.
- В среде разработки сервер назначает всех подключающихся агентов первой организации.
- Благодаря этому можно отлаживать агента и сервер вместе и видеть своё устройство в списке.

### Непрерывная интеграция

Файл `.github/workflows/ci.yml` на каждый push и pull request в `master` собирает решение на Windows, запускает тесты `Shared.Tests` и `Server.Tests` и проверяет все проекты на уязвимые NuGet-пакеты (прямые и транзитивные). Найденная уязвимость делает проверку красной.

## Сборка агентов

Агент и клиент удалённого рабочего стола собираются под каждую платформу. Скрипт `Utilities/Publish.ps1` собирает всё сразу, но требует найденный `vswhere`/MSBuild из Visual Studio. Если Visual Studio нет, выполните шаги вручную. Пример для Windows x64:

```
dotnet publish Agent/Agent.csproj -p:Version=ВЕРСИЯ -p:FileVersion=ВЕРСИЯ --runtime win-x64 --self-contained --configuration Release --output Agent/bin/publish/win-x64
dotnet publish Desktop.Win/Desktop.Win.csproj -p:Version=ВЕРСИЯ -p:FileVersion=ВЕРСИЯ -p:PublishProfile=packaged-win-x64 --configuration Release
```

Затем содержимое `Agent/bin/publish/win-x64` упаковывается в `Remotely-Win-x64.zip` и кладётся в `Server/wwwroot/Content`. Аналогично для `win-x86`. Автономные клиенты `Remotely_Desktop.exe` для скачивания с сайта собираются профилями `desktop-win-x64` и `desktop-win-x86`. В Git Bash параметры задавайте как `-p:...`, а не `/p:...`, иначе оболочка принимает их за путь.

### Обновление агентов

Каждый агент периодически отправляет запрос `HEAD /Content/Remotely-Win-x64.zip` (или `-x86`) и сравнивает ETag с сохранённым в `etag.txt`. Если файл на сервере изменился, агент скачивает и устанавливает новый пакет. Поэтому:

- **как только вы замените zip в `Content`, обновятся все агенты**, каждый при очередной проверке. Пробной выкладки на часть машин нет.
- чтобы проверить новую сборку, **установите её вручную на одну машину** скриптом `Install-Remotely.ps1` при ещё не изменённых zip на сервере: установщик запоминает текущий ETag, и такой агент не откатится назад;
- перед массовой раскаткой сохраните прежние zip, они понадобятся для отката (откат тоже запускает обновление всех агентов обратно).

## Учётные записи администраторов

Первая созданная учётная запись — администратор и сервера, и организации.

Администратор организации имеет доступ к странице Organization и к записям журнала сервера, относящимся к его организации. Администратор сервера имеет доступ к странице Server Config и видит записи журнала, не относящиеся ни к одной организации.

## Брендирование

В разделе Account есть вкладка брендирования, применяемая к клиентам быстрой поддержки и установщику Windows.

Чтобы клиенты могли получить данные брендирования, они должны быть собраны из исходников с жёстко заданным адресом сервера.

## Конфигурация

Провайдер базы данных, строки подключения и порт ASP.NET Core настраиваются переменными окружения в `docker-compose.yml`.

Остальные параметры задаются на странице Server Config после входа.

- AllowApiLogin: разрешить вход через контроллер API. Лучше использовать токены доступа API.
- BannedDevices: массив идентификаторов, имён или IP-адресов запрещённых устройств. При попытке подключения им сразу отправляется команда удаления.
- DataRetentionInDays: сколько дней хранятся журналы и другие данные на сервере. Значение -1 хранит бессрочно (не рекомендуется).
- DBProvider: выбирает одну из трёх строк подключения. Подходящий провайдер загружается автоматически.
- EnableWindowsEventLog: дублировать записи журнала сервера в журнал событий Windows.
- EnforceAttendedAccess: клиенту будет показан запрос на разрешение неконтролируемых попыток удалённого управления.
- EnableRemoteControlRecording: сохранять записи сеансов удалённого управления на сервере.
  - Они сохраняются в `/app/AppData/recordings`.
  - Срок хранения определяет `DataRetentionInDays`.
- ForceClientHTTPS: принудительно использовать схему HTTPS в установщиках и клиентах, даже если пересылаемые заголовки настроены неверно.
- KnownProxies: если обратный прокси работает на другой машине и пересылает запросы серверу, добавьте его IP в этот массив.
- MaxOrganizationCount: по умолчанию на сервере может существовать одна организация, она создаётся при регистрации первой учётной записи, после чего саморегистрация отключается.
  - Значение -1 или большее число включает мультиарендность.
- RedirectToHttps: перенаправлять ли ASP.NET Core весь трафик с HTTP на HTTPS. Не зависит от настроек Caddy, Nginx и IIS.
- RemoteControlNotifyUsers: показывать конечному пользователю уведомление при начале неконтролируемого сеанса удалённого управления.
- RemoteControlRequiresAuthentication: требовать ли аутентификацию для страницы удалённого управления.
- Require2FA: требовать настройки двухфакторной аутентификации перед использованием приложения.
- Smtp-: параметры SMTP для автоматических системных писем (регистрация, сброс пароля).
- Theme: цветовая тема сайта, «Light» или «Dark». Можно задать и для пользователя в Account - Options.
- TrustedCorsOrigins: для кросс-доменных запросов к API из JavaScript. Сайты из этого массива смогут обращаться к API. Это не заменяет аутентификацию, она по-прежнему нужна для большинства конечных точек.
- UseHsts: использовать ли ASP.NET Core HTTP Strict Transport Security.
- UseHttpLogging: включает журналирование всех HTTP-запросов, а также дополнительные записи в `ClientDownloadsController` о фактической схеме, адресе и IP после обработки пересылаемых заголовков.
  - Для работы нужно явно задать уровень журнала для `Microsoft.AspNetCore.HttpLogging.HttpLoggingMiddleware`. Пример см. в [appsettings.json](Server/appsettings.json).

## Смена базы данных

По умолчанию используется база SQLite. При первом запуске создаётся файл, указанный в строке подключения SQLite в `appsettings.json`.

Чтобы сменить базу, измените `DBProvider` в `ApplicationOptions` на `SQLServer` или `PostgreSQL`. Миграции для всех трёх провайдеров лежат в `Server/Migrations`, схема при этом совпадает.

## Журналирование

- На клиентах журналы лежат в `%ProgramData%\Remotely\Logs`.
- В контейнере сервера журналы пишутся в `/app/AppData/logs` (по умолчанию это `/var/www/remotely/Logs` на хосте).
- Встроенные журналы ASP.NET Core пишутся в консоль (stdout), их можно перенаправить в файл.
  - В IIS это делается параметром stdoutLogEnabled в web.config.
- На серверах Windows журналы также можно писать в журнал событий Windows.
  - Включается параметром EnableWindowsEventLog в Server Config.
- Уровни журналов и другие параметры задаются в appsettings.json.
  - Подробнее: https://docs.microsoft.com/en-us/aspnet/core/fundamentals/logging/

## Требования к клиентам удалённого управления

- Windows: проверяется только последняя версия Windows 11. Windows 7 и 8.1 должны работать, но на Windows 7 производительность ниже. Windows Server 2019/2022 должны работать, но регулярно не проверяются.
- Linux: проверяется только последняя LTS-версия Ubuntu.
- Для клиента «быстрой поддержки» в Ubuntu сначала установите зависимости:
  - libx11-dev
  - libxrandr-dev
    - libc6-dev
    - libxtst-dev
    - xclip
- Ввод с клавиатуры на Linux: символы вне ASCII передаются как Unicode-keysym (`U044F`), но набираются только если такая раскладка есть в сеансе X11.

## Удалённое управление с мобильного устройства

Лучше управлять с настоящего компьютера или ноутбука, но удалённое управление сделано хотя бы отчасти пригодным и для мобильных устройств:

- Левый клик: одно касание
- Правый клик: долгое нажатие, затем отпустить
- Перетаскивание: долгое нажатие, затем перемещение

## Страница поддержки конечных пользователей

На странице `/get-support` конечные пользователи могут запросить поддержку. После отправки формы над таблицей на главной странице появляется оповещение.

Ярлык этой страницы создаётся в папке `\Program Files\Remotely\`. Его можно скопировать куда угодно или автоматически поместить на рабочий стол ключом `-supportshortcut` установщика.

## Развёртывания .NET

- Есть два способа развёртывания: зависящее от фреймворка и самодостаточное.
  - Зависящее от фреймворка требует установленной среды выполнения .NET той же версии, что использовалась при сборке.
  - Самодостаточное включает копию среды выполнения, поэтому устанавливать её на целевые компьютеры не нужно, но размер файлов намного больше.
- При сборке используются идентификаторы среды выполнения (RID).
  - Ссылка: https://docs.microsoft.com/en-us/dotnet/core/rid-catalog

## Горячие клавиши консоли

- `/` — переключение между оболочками. Названия настраиваются на странице Options.
- Вверх/вниз — перебор истории ввода.
- Ctrl + Q — очистка окна вывода.

## Настройка портов

Порт хоста (слева) можно изменить в `docker-compose.yml`. Порт контейнера (справа) менять не следует. Подробнее в [документации compose](https://docs.docker.com/compose/compose-file/05-services/#ports).

## API и интеграции

У Remoton есть базовое API, которое можно посмотреть по адресу `https://{адрес_вашего_сервера}/swagger`. Для большинства конечных точек нужна аутентификация токеном доступа API (Account - API Access).

При обращении к API из браузера с другого сайта настройте CORS в appsettings: добавьте адрес сайта в массив TrustedCorsOrigins. Если вы не знакомы с CORS, сначала почитайте о нём. Например, чтобы форма входа на https://example.com работала с API Remoton, добавьте «https://example.com» в TrustedCorsOrigins.

В каждом запросе к API должен быть заголовок «X-Api-Key». Значение — идентификатор и секрет ключа через двоеточие (`[ApiKey]:[ApiSecret]`).

Пример запроса к API:

    POST https://localhost:5001/API/Scripting/ExecuteCommand/PSCore/f2b0a595-5ea8-471b-975f-12e70e0f3497 HTTP/1.1
    Content-Type: application/json
    X-Api-Key: 31fb288d-af97-4ce1-ae7b-ceebb98281ac:HLkrKaZGExYvozSPvcACZw9awKkhHnNK
    User-Agent: PostmanRuntime/7.22.0
    Accept: */*
    Cache-Control: no-cache
    Host: localhost:5001
    Accept-Encoding: gzip, deflate, br
    Content-Length: 12
    Connection: close

    Get-Location

Примеры входа через API по cookie (JavaScript):

    // Вход одним запросом, затем запуск удалённого управления другим.
    fetch("https://localhost:5001/api/Login/", {
    	method: "post",
    	credentials: "include",
    	mode: "cors",
    	body: '{"email":"email@example.com", "password":"P@ssword1"}',
    	headers: {
    		"Content-Type": "application/json",
    	}
    }).then(response=>{
    	if (response.ok) {
    		fetch("https://localhost:44351/api/RemoteControl/Viewer/b68c24b0-2c67-4524-ad28-dadea7a576a4", {
    			method: "get",
    			credentials: "include",
    			mode: "cors"
    		}).then(response=>{
    			if (response.ok) {
    				response.text().then(url=>{
    					window.open(url);
    				})
    			}
    		})
    	}
    })

    // Вход и запуск удалённого управления одним запросом.
    fetch("https://localhost:5001/api/RemoteControl/Viewer/", {
    	method: "post",
    	credentials: "include",
    	mode: "cors",
    	body: '{"email":"email@example.com", "password":"P@ssword1", "deviceID":"b68c24b0-2c67-4524-ad28-dadea7a576a4"}',
    	headers: {
    		"Content-Type": "application/json",
    	}
    }).then(response=>{
    	if (response.ok) {
    		response.text().then(url=>{
    			window.open(url);
    		})
    	}
    })

## Оповещения (Alerts)

API оповещений позволяет добавить мониторинг и оповещения для конечных устройств. Функция даёт базовые возможности RMM, не уводя проект далеко от его основной задачи.

Оповещение может показать уведомление на сайте Remoton, отправить письмо и/или выполнить отдельный запрос к API.

Чтобы использовать оповещения, сначала создайте токен (или несколько) API для ваших устройств, затем создайте запланированное задание или другой периодический скрипт. Ниже пример задания PowerShell, которое ежедневно проверяет свободное место на диске.

```
$Trigger = New-JobTrigger -Daily -At "5 AM"
$Option = New-ScheduledJobOption -RequireNetwork

Register-ScheduledJob -ScriptBlock {
    $OsDrive = Get-PSDrive -Name C
    $FreeSpace = $OsDrive.Free / ($OsDrive.Used + $OsDrive.Free)
    if ($FreeSpace -lt .1) {
        Invoke-WebRequest -Uri "https://localhost:5001/api/Alerts/Create/" -Method Post -Headers @{
            X-Api-Key="3e9d8273-1dc1-4303-bd50-7a133e36b9b7:S+82XKZdvg278pSFHWtUklqHENuO5IhH"
        } -Body @"
            {
                "AlertDeviceID": "f2b0a595-5ea8-471b-975f-12e70e0f3497",
                "AlertMessage": "Мало места на диске. Свободно: $([Math]::Round($FreeSpace * 100))%",
                "ApiRequestBody": null,
                "ApiRequestHeaders": null,
                "ApiRequestMethod": null,
                "ApiRequestUrl": null,
                "EmailBody": "Мало места на диске устройства Maker.",
                "EmailSubject": "Оповещение о месте на диске",
                "EmailTo": "admin@example.com",
                "ShouldAlert": true,
                "ShouldEmail": true,
                "ShouldSendApiRequest": false
            }
"@ -ContentType "application/json"
    }
} -Name "Check OS Drive Space" -Trigger $Trigger -ScheduledJobOption $Option
```
